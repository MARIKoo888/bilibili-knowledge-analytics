## 第 1 节 · 均值 vs 中位数（做 Q1 前必看）

**一句话**：均值 = 所有人分蛋糕后每人拿多少；中位数 = 排队站中间那个人的蛋糕大小。

**为什么需要**：B站播放量是典型的"极端值长尾"——绝大多数视频几千播放，个别爆款几千万。

```
举例：7 条视频的播放量
  800, 1200, 1500, 2000, 3000, 5000, 2000000   ← 最后一个是爆款
  均值   = 287500   ← 被那一条爆款拉到 28 万
  中位数 = 2000     ← 站在正中间那条，真实反映"典型视频"
```

**结论**：均值告诉你"这个分区总共有多少播放"，中位数告诉你"**一条普通视频能拿多少播放**"。
做"这个选题值不值得做"的判断时，**必须看中位数**——否则你会得出"知识区平均播放 28 万，很好做"这种荒谬结论（实际一条普通视频只有 2000）。

**本项目用在哪**：Q1 的需求量、Q2 的因变量、第 7–9 周所有 SQL 的默认口径。

**动手练**：
```
给你 8 条视频的点赞数，求均值和中位数：
  10, 12, 15, 20, 22, 30, 45, 900

均值 = ?       中位数 = ?
差值说明了什么？
```
<details><summary>答案（先自己做）</summary>

均值 = (10+12+15+20+22+30+45+900)/8 = 1054/8 = **131.75**
中位数 = 第 4、5 个的平均 = (20+22)/2 = **21**
差 6 倍多 → 说明有极端值（那个 900），**中位数才代表"典型视频"**。
</details>

## 第 2 节 · 供需比（做 Q1 用）

**一句话**：供给 ÷ 需求。比值越高 = 越多人抢同一块蛋糕 = 越内卷。

**为什么需要**："这个选题好不好做"不能只看播放高不高——播放高可能只是因为**发的人少**（供给少），也可能因为**大家就是爱看**（需求高）。要分开看。

```
供给量 = 该细分方向下有多少条视频      ← "多少人在做"
需求量 = 该细分方向视频的播放中位数    ← "一条普通视频能拿多少播放"

供需比 = 供给量 ÷ 需求量
  比值高 → 一堆人在发，但每条都没量 → 供过于求（红海，别进）
  比值低 → 发的人少，但每条都有量   → 供不应求（机会，优先做）
```

**⚠️ 常见错误**：分子分母写反。记住口诀——"**谁多谁在上面**"，你要找的是"人多肉少"的方向。

**本项目用在哪**：Q1 的核心指标 → 第 9 周的供需热度矩阵 → 简历里那条"识别出 3 个供不应求方向"。

**动手练**：
```
方向 A：120 条视频，播放中位数 8000
方向 B： 25 条视频，播放中位数 30000

(a) 两个方向的供需比分别是多少？
(b) 你是运营，下周先做哪个方向？为什么？
```
<details><summary>答案（先自己做）</summary>

(a) A = 120/8000 = **0.015**；B = 25/30000 = **0.00083**
(b) 选 **B**。B 的供需比更低 = 供给少、需求高 = **供不应求**；A 是 120 个人在抢 8000 的量，红海。
> 注意：这只是简化版。真实分析还要**控制分区和 UP 主体量**（见第 3 节），否则 B 可能只是"恰好有 2 个大 UP 主在发"。
</details>

## 第 3 节 · 控制变量（做 Q2 用，**全项目最值钱的一节**）

**一句话**：要比较 A 对结果的影响，必须先保证**其他会造成差异的因素都一样**。

**为什么需要**——这是新手最容易翻车的地方：
```
现象：时长 >30 分钟的视频，播放量明显更高。
天真结论："做长视频更容易火！"

真相：做 30 分钟以上长视频的，大多是粉丝几十万的大 UP 主
      （小 UP 主不敢做长视频）。所以高播放来自"UP 主本来就火"，
      不是"视频长"。

→ 你比较的其实是"UP 主体量"，不是"时长"。这个混淆因素叫 confounder。
```

**怎么控制**（本项目的做法）：
1. **只在同一个分区内比较**（知识区和鬼畜区的播放不可比）
2. **把 UP 主粉丝量分档**：如 <1万 / 1–10万 / >10万，**在每一档内部**比较时长
3. 只有当"在同一粉丝档内，长视频依然更好"时，才能说时长有效

**面试怎么讲**（背下来）：
> "我比较时长对播放的影响时，控制了分区和 UP 主粉丝量分档——因为长视频的创作者往往本身粉丝基数大，不控制的话，我测的其实是 UP 主体量，不是时长。"

**本项目用在哪**：Q2 的"必须控制的变量"栏、第 8 周周六的归因实验、第 12 周的偏差章节。

**动手练**：
```
某分区数据：
  <1万粉 UP 主：短视频中位播放 3000，长视频中位播放 2800
  1-10万粉 UP 主：短视频中位播放 15000，长视频中位播放 14000
  未分档时整体：短视频中位播放 5000，长视频中位播放 12000

(a) 为什么"整体比较"会得出"长视频更好"？
(b) 分档后真实结论是什么？
(c) 这个例子里的混淆因素是什么？
```
<details><summary>答案（先自己做）</summary>

(a) 因为长视频大多由大粉丝 UP 主产出，把大 UP 主的高播放算到了"长视频"头上。
(b) **分档后每一档里，长视频都不如短视频** → 时长没有正效果，整体结论是假的。
(c) 混淆因素 = **UP 主粉丝量**。这就是为什么必须先分档。
</details>

## 第 4 节 · 口径与分母（做任务 3、Q2 用）

**一句话**：说一个指标，必须同时说清"分子是什么、分母是什么"。

**为什么需要**：同样叫"互动率"，除以播放和除以点赞，结论能完全相反。**口径不统一，两个部门的数就对不上。**

```
互动率 = (点赞 + 投币 + 收藏) / 播放
         ↑ 分子：算哪些互动？  ↑ 分母：除以谁？

为什么分母常用"播放"而不是"点赞"？
  → 播放是最大的曝光口径，覆盖最广，最稳定。
  → 但注意：播放是累计快照值，会一直涨，所以必须声明"数据截取时间"。

为什么知识区特别要看"收藏率"（收藏/播放）？
  → 收藏 = "这个我以后要用" = 有用性，这是知识类内容的核心价值。
```

**动手练**：
```
视频甲：播放 10万，点赞 5000，投币 1000，收藏 2000
视频乙：播放  1万，点赞 1200，投币  400，收藏  900

(a) 分别算两条的互动率（用上面口径）
(b) 哪条内容"质量"更高？如果只看点赞数你会选错吗？
```
<details><summary>答案（先自己做）</summary>

(a) 甲 = (5000+1000+2000)/100000 = **8.0%**；乙 = (1200+400+900)/10000 = **25.0%**
(b) **乙**的质量更高（互动率 25% vs 8%）。但甲的**绝对点赞数**（5000）远高于乙（1200）——只看点赞数会误判甲更好。这就是"必须看比率、不能只看绝对值"的原因。
</details>
