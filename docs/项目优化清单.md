# 项目优化清单（按面试价值 / 工时排序）

> 生成时间：2026-10-27
> 用途：项目收尾期的"加什么、砍什么、先后顺序"决策依据。
> 判断标准：**这一项会让面试官多问一个问题，还是只是让项目看起来更满？**

---

## 背景：为什么这样排序

2026 年的数据岗市场已经分成两半（参考《Data Agent 来了，数据分析师还有活路么？》，数据猿 2026-10）：
- **执行层**（取数、清洗、出报表）→ AI 正在替代，岗位收缩
- **判断层**（定义口径、验证结论、为数字负责）→ AI 碰不动，岗位缺人

**所以项目优化的核心目标只有一个：把"判断层"的证据做得更硬、更可展示。**
凡是只让"执行层"看起来更花哨的东西（更多图表、更炫的界面），优先级一律降低。

## 明确不做的清单（避免被"看起来更专业"诱惑）

| 不做 | 原因 |
|---|---|
| Docker / K8s | 数据岗 JD 不要求，写了会被追问到底 |
| Spark / Flink / Hadoop | 数据量 10 万行以内，**用 Spark 是过度设计**；但要在面试里主动说"我知道边界在哪" |
| BERT / 深度学习情感模型 | 你是分析岗不是算法岗；而且实测弹幕 88% 中性，**换模型也救不回来**（问题在数据，不在模型） |
| 更多分区/更多关键词的采集 | 采集够了；再堆数据不产生新洞察 |
| 完美主义式美化 | 第12周的稿子一定不完美，先完成再完美 |

## 关键提醒：关于「补 FineReport / Power BI」

**只学一个，别都学。** 选择依据是目标岗位类型：

| 目标岗位 | 学哪个 | 理由 |
|---|---|---|
| 互联网中厂业务分析 / 数据运营 | **Power BI** | 内部 BI 体系主流；DAX 能体现度量值思维 |
| BI 厂商实施 / 售前 / 解决方案 | **FineReport（帆软）** | 帆软在国内中小企业覆盖率极高，实施岗招本科多、门槛低于分析师 |
| 外企 / 咨询 / 快消 | **Tableau** | 视觉表达优先 |

**学习方式建议（别报课）**：拿你现有的 MySQL 数据，做 3 页仪表盘——
1. 总览（KPI 卡 + 趋势）
2. 分区对比（供需/竞争度）
3. 内容拆解（时长 × 播放）
做完截图进作品集。**3 页足够，别做 10 页。**

## 优先级建议（按剩余时间）

```
若只剩 10 个会话：  做 P0 全部（1–6）
若剩 15 个会话：    P0 + 第 7 项（口径治理专题）
若剩 20 个会话：    P0 + P1（7、8、9）
```
