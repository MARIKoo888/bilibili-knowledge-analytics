## 从命名表里能读出的三条业务发现

### ① 最大簇是"杂谈"，说明弹幕高度碎片化

簇 3 占 **42.6%**，内容没有共同主题（"国考也是省考也是"这类随口一句）。
→ 说明**弹幕不适合做主题分类**，它更像"实时弹幕墙"，而非"结构化评论"。
→ 这也解释了为什么轮廓系数只有 0.0565。

### ② 有信息量的簇里，"薪资"是最大主题（12.3%）

簇 0 全是谈薪、工资、待遇讨论，且语气很实用（"直接问薪酬待遇、工资结构、工作压强"）。
→ **选题含义**：薪资类内容有强需求，且用户会主动讨论具体做法，**适合做"可操作步骤"型内容**（怎么问、问什么、怎么还价）。

### ③ ⚠️ 装修施工内容占 8.3%，是重要的数据噪声

簇 6 整整 1,008 条（8.3%）是装修/施工讨论（防水、瓷砖、水泥、发泡胶）。
→ **原因**：「职业职场」分区里混着一批装修施工技能教学视频（此前在 SQL#4 已发现）。
→ **影响**：该垂类的语料并非纯"职场软技能"，占比比按词频估计的 0.5% 大得多（因为这一类会整簇聚在一起）。
→ **处理**：本报告在"数据可信度"章节声明；后续如做严肃职场文本分析，应先按视频标题过滤掉施工/考证类内容。

### ④ 「缺点」形成一个独立小簇，验证了它是高频梗

簇 5 仅 150 条，但内容高度一致（"我的缺点是太完美"的各种变体）。
→ 面试"问缺点"是一个**用户高度共鸣的梗**，适合做轻松化选题（例如"面试官问缺点，这样答不踩雷"）。

## 局限（必须写进报告）

1. **轮廓系数 0.0565**，远低于 0.25 的"有结构"门槛。短文本聚类固有难题，本报告**不宣称完成主题分类**，只作"话题倾向的粗分组"。
2. **首次直接对 TF-IDF 矩阵聚类时崩溃**：最大簇占 94.1%、轮廓系数 0.0125。加 SVD 降维后改善到 42.6%。
3. 簇的边界是模糊的（如簇 8 混合了"内容评价"和"面试经历"），命名带主观性。
4. 未使用词向量（word2vec/BERT）——那需要预训练模型，超出本项目范围。
